OpenAI Schnittstellen-Spezifikationen

Übersicht der technologischen Möglichkeiten und Integrationen der neuesten OpenAI Modelle im Kontext des ZEEMLESS Voice & Chat Interfaces für komplexe Projektplanungen.

Voice & Multimodale Interaktion

Realtime API (WebRTC)

Ermöglicht Low-Latency, bidirektionale Sprachkommunikation in Echtzeit. Ideal für flüssige Interview-Prozesse per Smartphone oder Browser-App (Barcode Scan -> Web App öffnen).

  • Unterstützung für Text und Audio via WebSocket oder WebRTC Protokoll.
  • Geringe Latenz: Natürliches Gesprächsgefühl ohne störende Verzögerungen.
  • Voice Activity Detection (VAD) zur automatischen Sprecherkennung.

GPT-4o (Omni) Modelle

Nativ multimodale Modelle (z.B. gpt-4o oder gpt-4o-realtime-preview), die direkt Sprache zu Spracheingabe/-ausgabe verarbeiten, ohne separate Speech-to-Text-Zwischenschritte.

  • Besseres Verständnis von Betonung, Dialekten und Unterbrechungen.
  • Schnellere Audio-Generierung als kaskadierte Systeme (Whisper + TTS).

Datenintegration & Logik (Model Context Protocol)

Function Calling & Tools

Das Modell kann definiert Tools trigger, um Aktionen in der UI auszuführen oder Datenbanken abzufragen. Dies ist das Herzstück zur Aktualisierung der UI (Links Chat, rechts farbige Daten-Panel).

  • State-Updates: Trigger-Events, um Felder in der UI von "Unbeantwortet (Gelb)" auf "Beantwortet (Grün)" zu setzen.
  • MCP-Bridge: Aufruf des sicheren Model Context Protocol Servers.

Structured Outputs (JSON Mode)

Erzwingt vom Sprachmodell eine strikte JSON-Strukturübereinstimmung basierend auf einem JSON-Schema. Garantiert, dass die Plattform die Antworten fehlerfrei verarbeiten und speichern kann.

  • Strikte Einhaltung von Datentypen (Strings, Integers, Arrays).
  • Ideal zum Sammeln der Parameter (Branchen, Systeme, Migrationstyp).

Verschlüsselung, Datenschutz & Sicherheit

Der Schutz hochsensibler Unternehmensdaten (wie SAP-Cutover Details der Deutschen Telekom) steht an oberster Stelle.

Zero Data Retention (ZDR)

Für Enterprise-Kunden kann ZDR aktiviert werden. OpenAI speichert die API-Anfragen (Prompts) und Antworten (Audio/Text) nicht ab und verwendet diese nicht für das Modell-Training (standardmäßig für API-Nutzer deaktiviert).

End-to-End Encryption (TLS)

Alle Daten-Transits (Audio-Streams, MCP WebSockets, REST-Abfragen) erfolgen über TLS 1.2+ oder DTLS-SRTP (im Falle von WebRTC). Damit sind Metadaten und Nutzdaten vor Man-in-the-Middle geschützt.

Ephemeral Tokens (WebRTC)

Im Web-App Szenario generiert das ZEEMLESS Backend ein kurzlebiges, signiertes Token, anstatt den direkten API-Key in den Client zu laden. Über dieses Token verbindet sich die Browser/Mobile-App sicher mit OpenAI.

Private Link / VPC Peering

Für streng regulierte Umgebungen können Azure OpenAI Instanzen in einem privaten virtuellen Netzwerk (VNet) betrieben werden, um den externen Internet-Traffic vollständig zu umgehen.
